대상: `peacock_brand_project` 스토리보드 S01(티아라 중앙 보석 클로즈업, 0–3초)

## 1. Blender MCP 연결 구조

```text
Claude Code ──(stdio)── blender-mcp 서버(uvx) ──(TCP 127.0.0.1:9876, JSON)── Blender 애드온 ── bpy
```

연결하려면 세 가지가 모두 갖춰져야 한다. 하나라도 없으면 "연결 안 됨"이다.

| 구성 요소 | 확인 방법 | 이번 실습에서 처음 확인한 상태 |
|---|---|---|
| MCP 서버 등록 | `claude mcp list` | 미등록 |
| Blender 실행 + 애드온 활성화 | 9876 포트 LISTEN 여부 | Blender 미설치 |
| 서버 실행 도구 `uvx` | `uvx --version` | 미설치 |

설치 순서는 다음과 같다.
1. `uv` 설치: `irm https://astral.sh/uv/install.ps1 | iex`
2. Blender 설치: `winget install --id BlenderFoundation.Blender -e`
3. 애드온 설치: blender-mcp의 `addon.py`를 설치하고 활성화한 뒤 사용자 설정을 저장한다. 자동 시작(Auto-Start)이 기본으로 켜져 있어서, 이후에는 Blender를 켜기만 하면 9876 포트가 열린다.
4. 서버 등록: `claude mcp add blender -- uvx blender-mcp`

### 주의할 점
- **MCP 도구는 세션을 다시 시작해야 로드된다.** 세션 도중에 등록한 서버는 `✔ Connected`로 나와도 현재 세션에서는 `mcp__blender__*` 도구가 보이지 않는다.
- 세션을 다시 시작할 수 없을 때는 애드온 소켓(9876)에 JSON을 직접 보내도 된다. MCP 서버가 쓰는 것과 같은 경로다. 예: `{"type":"ping"}`, `{"type":"get_scene_info"}`, `{"type":"execute_code","params":{"code":"..."}}`
- `ping`은 bpy 데이터를 건드리지 않는다. 연결 문제와 데이터 문제를 구분할 때 먼저 확인한다.

## 2. Blender 사용법: 공간 구성

장면은 아래 순서로 쌓는다.

1. **배경**: 월드 색과 바닥. 이번에는 딥 플럼 `#240923` 월드와 바닥 평면을 썼다.
2. **건물·구조물**: 큰 덩어리를 먼저 만든다. 이번 장면에서는 캐릭터 몸통, 머리, 꼬리 같은 큰 형태가 여기에 해당한다.
3. **자연·주변 요소**: 장면에 필요한 주변 오브젝트를 배치한다.
4. **디테일**: 장신구, 보석, 곡선 장식 같은 작은 요소를 더한다.
5. **텍스처·재질**: 지정된 색(HEX)을 선형 색으로 바꿔 Principled BSDF에 적용한다.

**블록아웃 작업이 끝나면 장면 스크린샷을 보여줘야 한다.**
- 숫자 로그만 보고는 문제를 못 찾는다. 이번 실습에서 실제로 겪은 사례:
  - 보석 외곽선의 점 순서가 꼬여 면이 깨졌다. 테스트 렌더를 보고서야 발견했다.
  - 조명이 너무 세서 몸통 자주색이 하얗게 날아갔다.
  - 와이드 컷에서 꼬리 양끝이 잘렸고, 얼굴에 눈이 없어 누구인지 알아보기 어려웠다.
- 그래서 저해상도(40%) 테스트 렌더나 뷰포트 스크린샷(`get_viewport_screenshot`)으로 확인한 뒤에 본 렌더로 넘어간다.

## 3. 프리비즈 제작에서 배운 점

- **기준 문서를 먼저 확인한다.** 요청에 나온 `video/shotlist.md`가 없어서, 같은 장면이 정의된 `storyboard_v1.md`의 S01을 기준으로 삼고 그 사실을 기록에 남겼다.
- **화면에 보이는 것만 만들면 나중에 막힌다.** v001은 매크로 컷이라 머리와 티아라만 만들었다. 그런데 "카메라 높이 1.6m"처럼 실제 단위로 요청이 들어오자, 바닥에 서 있는 실제 크기 캐릭터가 필요해졌다. 그래서 v002에 전신 블록아웃을 추가했다.
- **스케일은 처음부터 미터 단위로 잡는다.** 비율 문서(fixed.md §3.2: 머리 0.36H, 몸통 0.40H 등)를 H 하나에 묶어 두면 크기 변경이 쉽다. 이번에 쓴 H=1.30m는 문서에 없는 **가정값**이라 기록에 그렇게 표시했다.
- **고정 요소는 움직이지 않는다.** 보석은 모양을 바꾸면 안 되므로 애니메이션을 넣지 않았다. 카메라 푸시인과 반사광 이동만으로 연출했다.
- **승인된 원본은 덮어쓰지 않는다.** v001을 그대로 두고 v002를 새로 만들었다. 파일 이름은 `PEACOCK_01_S01_previz_v00N` 형식으로 맞췄다.
- **카메라는 Track To 제약으로 타깃을 겨냥한다.** 높이를 고정한 채 수평 거리만 키프레임으로 바꾸면 내려다보는 각도가 자연스럽게 변한다(14.8°→19.2°).
- **긴 렌더는 따로 돌린다.** MP4 애니메이션은 `blender -b 파일.blend --python 스크립트`로 백그라운드에서 렌더했다. 소켓으로 렌더하면 열려 있는 Blender 창이 멈추고, 요청 시간 초과 위험도 있다.
- **복사본 저장의 함정.** `save_as_mainfile(copy=True)`로 저장하면 디스크에 파일은 생기지만 열린 창은 계속 "제목 없음" 상태다. 이때 Save를 누르면 다른 이름으로 저장 창이 뜨고, 잘못 고르면 v001을 덮어쓸 수 있다. 창을 닫을 때는 "저장 안 함"을 고른다.
