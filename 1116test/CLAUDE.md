# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## 개요

이 폴더는 코드가 아니라 사업 타당성 분석 작업 공간이다. 빌드·린트·테스트는 없다.

- `playbook.md`: 어떤 아이디어에도 쓰는 기획 절차서(0~10단계)
- `market_model_case_student.xlsx`: 팀의 예시 모델. 대구 수성구 15개 동을 대상으로 한 가상 "D마트 즉시배송(퀵커머스)" 사업성 분석이다. 새 모델을 만들 때 시트 구성의 기준으로 삼는다. 아래 "시트 의존 구조" 이후 내용은 이 예시 파일에 대한 설명이다.
- `ideas/`: 새 아이디어별 작업 폴더

## 기획 작업은 playbook.md를 따른다

사업 아이디어 분석, 타당성 검토, 계획서·결과보고서 작성을 할 때는 **먼저 [playbook.md](playbook.md)를 읽고 그 0~10단계 순서대로 진행한다.**

- 단계마다 플레이북의 "구하는 것"을 산출하고, "타당성 확인" 항목을 모두 점검하고, "더 나은 방향" 질문에 대한 의견을 남긴다.
- 끝나면 플레이북의 "산출물 체크리스트"를 채워 보고한다. 하지 못한 단계는 이유와 함께 `[확인필요]`로 표시한다.
- 새 아이디어는 `ideas/<아이디어명>/` 폴더에 작업한다. 모델은 `model.xlsx`(예시 파일과 같은 시트 구성), 보고서는 `report.md`로 둔다. 새로 만드는 파일은 차트가 없으므로 openpyxl로 만들어도 된다.
- 서브에이전트(`.claude/agents/`)의 역할 분담은 다음과 같다.

| 플레이북 단계 | 담당 |
|---|---|
| 0. 아이디어·방안 정의 | 메인 세션 |
| 1. 자료 수집, 2. 가정 제안 | researcher |
| 2. 가정 반영 ~ 7. 민감도 (모델 작성·계산) | model-simulator |
| 8. 경쟁 분석, 9. 포지셔닝 | competitor-analyzer |
| 10. 종합 판단, 전 단계 타당성 점검 | reviewer |

## 단계별 실행 로그 (run_log.json)

플레이북 단계를 하나 끝낼 때마다 그 기록을 `ideas/<아이디어명>/run_log.json`에 남긴다. 예시 모델을 고칠 때는 `1116test/run_log.json`에 남긴다.

- **기록하는 쪽:** 메인 세션만 파일에 쓴다. researcher와 competitor-analyzer가 동시에 돌 수 있어서, 여러 쪽이 같이 쓰면 기록이 덮어써질 수 있기 때문이다. 서브에이전트는 결과 끝에 아래 항목을 담은 "로그 요약"을 붙여 돌려주고, 메인 세션이 그것을 옮겨 적는다.
- **추가만 한다:** 기존 기록은 고치거나 지우지 않는다. 같은 단계를 다시 하면 새 기록을 추가하고 `rerun_of`에 이전 기록의 `id`를 적는다.
- **올바른 JSON을 유지한다:** 기록을 추가한 뒤 파일 전체가 JSON으로 읽히는지 확인한다(`python -I -X utf8 -c "import json;json.load(open('run_log.json',encoding='utf-8'))"`).
- **숫자 규칙은 보고서와 같다:** 로그에 적는 숫자도 모델 셀에서 가져오고 출처 셀을 적는다. 모르는 값은 `"[확인필요]"`로 쓴다.
- 시각은 한국 시간 ISO 8601 형식으로 쓴다(예: `2026-11-16T14:05:00+09:00`).

형식:

```json
{
  "idea": "아이디어 한 줄",
  "model_file": "ideas/<아이디어명>/model.xlsx",
  "entries": [
    {
      "id": 1,
      "step": 3,
      "step_name": "시장 규모",
      "agent": "model-simulator",
      "started_at": "2026-11-16T14:00:00+09:00",
      "finished_at": "2026-11-16T14:05:00+09:00",
      "status": "완료",
      "inputs": ["가정!C5:E9", "자료!B15"],
      "outputs": ["시장규모!B4:D26"],
      "key_results": [
        {"name": "기준 월 주문 수", "value": 5607, "cell": "시장규모!C16", "구분": "가정"}
      ],
      "validation": [
        {"check": "상향식 ÷ 하향식", "result": "통과", "note": "9.0%, 선택 비율 가정 10%와 비슷"}
      ],
      "better_direction": ["시장 범위를 인접 동까지 넓히는 안 검토"],
      "needs_check": ["[확인필요] 2025년 주문 건수"],
      "decisions": [{"decision": "결정 내용", "reason": "근거"}],
      "rerun_of": null
    }
  ]
}
```

- **대시보드가 읽는 항목**(필수):
  - 5단계 기록에는 `pnl`을 넣는다. 형식: `[{"plan": "A안", "scenario": "보수", "value": -30530123, "cell": "손익!B12"}, ...]`. 모든 방안 × 보수·기준·낙관을 빠짐없이 넣는다. 새 모델은 openpyxl로 만들어 엑셀 캐시값이 없으므로, 대시보드 손익 그래프는 이 값으로 그린다.
  - reviewer 기록에는 `findings`를 넣는다. 형식: `[{"severity": "높음|중간|낮음", "issue": "무엇이 문제인지", "location": "셀 또는 문서 위치", "rule": "위반한 플레이북 단계·규칙", "fix": "고칠 방법"}]`. 지적이 없으면 빈 배열 `[]`을 넣는다.
  - 10단계 기록에는 `conclusion`을 넣는다. 형식: `{"verdict": "가|부|조건부 시행", "conditions": ["조건 (출처 셀)", ...]}`.
- `status`는 `완료` / `미흡` / `실패` / `건너뜀` 중 하나를 쓴다. `미흡`이나 `건너뜀`이면 `needs_check`에 이유를 적는다.
- `validation`은 플레이북 해당 단계의 "타당성 확인" 항목을 하나씩 옮겨 적는다. `result`는 `통과` / `주의` / `실패`이다.
- `better_direction`은 플레이북 해당 단계의 "더 나은 방향" 질문에 대한 의견이다.
- 10단계 기록의 `key_results`에는 결론(가 / 부 / 조건부 시행)과 조건을 넣는다.

## 에이전트 대시보드

`python -X utf8 dashboard_server.py`를 실행하고 `http://127.0.0.1:8765`를 연다. `dashboard.html`을 파일로 직접 열면 동작하지 않는다.

- **실행 버튼:** 입력한 아이디어로 `ideas/<아이디어>-<월일-시분>/` 폴더를 만들고, `claude -p`(stream-json 출력)로 플레이북 절차를 실행한다. 사용할 수 있는 도구는 `Agent, Read, Write, Edit, Glob, Grep, WebSearch, WebFetch, Bash`로 미리 허용되어 있다. 실행 중에는 사용자에게 질문할 수 없으므로 결정 사항은 run_log의 `decisions`에 남긴다. 아이디어를 비워 두고 실행하면 예시 모델(`market_model_case_student.xlsx`)을 플레이북 절차로 분석한다. 이때 기록은 `./run_log.json`, 보고서는 `./report.md`에 남기고 원본 엑셀은 수정하지 않는다.
- **중지 버튼:** claude 프로세스 트리를 강제 종료한다(`taskkill /T /F`). 작업 중이던 에이전트는 "중지됨"으로 표시된다. 작성 중이던 파일이 중간 상태로 남을 수 있다.
- **에이전트 상태:** claude 출력의 Agent 도구 호출·서브에이전트 메시지와, `dashboard_hook.py`가 남기는 SubagentStart/SubagentStop 훅 이벤트로 판단한다. 실행 중 상태 파일은 `.dashboard/`에 쌓인다(git 제외).
- **화면 데이터:** 에이전트 카드의 run_log는 `agent` 값으로 나눠 보여 준다. 손익 그래프는 5단계 `pnl`, 없으면 모델 엑셀의 손익 시트 캐시값을 쓴다. 지적사항은 reviewer의 `findings`, 결론은 10단계 `conclusion`을 쓴다.
- 서버는 127.0.0.1에서만 열리고, 다른 사이트에서 보낸 실행 요청은 거부한다(`X-Dashboard` 헤더와 Origin 검사).

## 계획서·결과보고서 작성 규칙 (반드시 지킬 것)

1. **모든 숫자는 엑셀에서 가져온다.** 계획서나 보고서에 쓰는 숫자는 모두 분석 대상 모델(엑셀)의 셀 값이어야 한다. 직접 계산하거나 외부에서 가져온 숫자를 쓰지 않는다. 출처 셀(예: `손익!F12`)을 함께 적는다.
2. **'가정' 값은 가정이라고 밝힌다.** 가정 시트 F열의 구분이 "가정"(또는 "자료/가정")인 항목, 그리고 그 값으로 계산된 결과를 쓸 때는 본문에 "(가정)"이라고 표시한다.
3. **엑셀에 없는 내용은 지어내지 않는다.** 엑셀에 근거가 없는 숫자나 사실은 쓰지 않고, 필요한 자리에는 `[확인필요]`라고 표시한다. 자료!B12처럼 엑셀에서 비어 있거나 "미확인"인 값도 `[확인필요]`로 쓴다.
4. **불리한 숫자를 빼거나 낙관 시나리오만 쓰지 않는다.** 보수·기준·낙관 세 시나리오와 A·B 두 방안의 결과를 모두 제시한다. 적자, "도달 불가", 민감도 분석에서 불리한 결과도 그대로 싣는다.
5. **결론은 '가', '부', '조건부 시행' 중 하나로 낸다.** "조건부 시행"이라면 어떤 조건인지를 엑셀 수치(예: 손익분기 일 주문 수, 민감도에서 흑자로 바뀌는 가정)로 구체적으로 적는다.
6. **자료를 모을 때는 값, 기준 시점, 출처, URL을 함께 적는다.** 자료 시트의 B열(값), D열(기준 시점), E열(출처), F열(URL)에 해당한다. 넷 중 찾지 못한 항목은 비워 두지 말고 그 칸에 `미확인`이라고 쓴다.
7. **가정을 제안할 때는 보수·기준·낙관 세 값을 함께 낸다.** 가정 시트의 C·D·E열에 맞추고, G열에는 세 값을 그렇게 정한 근거를 적는다.
8. **엑셀의 계산은 반드시 수식으로 건다.** 계산 결과를 숫자로 직접 입력하지 않는다. 다른 셀에서 가져오는 값도 셀 참조(예: `=자료!$B$16`)로 연결한다. 직접 입력해도 되는 것은 원자료 값과 가정 값뿐이다.

## 시트 의존 구조

값은 아래 순서로 흘러간다. 입력은 **자료**와 **가정**에만 있고, 나머지 시트는 모두 수식이다.

```
자료 ─┬─> 가정 ─┬─> 시장규모 ─> 손익 ─> 계단표
      │         ├─> 단위경제 ─┘
      │         └─> 민감도 (단위경제·손익 공식을 독립적으로 다시 계산)
      └─> 시장규모 (하향식 TAM·SAM, B마트 교차 확인)
경쟁비교 ─> 포지셔닝 (텍스트·점수 참조, 차트 1개 포함)
```

- **가정**: 열 C/D/E = 보수/기준/낙관. 다른 시트는 이 열 위치로 시나리오를 고른다. 단위경제·손익 시트는 B~D열이 A안(전용 창고), E~G열이 B안(매장 재고 공유)이다.
- **민감도**: B안 기준 시나리오만 쓴다. N열(건당 공헌이익)과 P열(월 손익)은 단위경제·손익 공식을 복제한 것이다. 한쪽 공식을 고치면 다른 쪽도 함께 고쳐야 한다.
- **손익!15행 손익분기**는 피커가 늘 완전 가동한다고 보고 계산한다. 인건비가 계단식으로 오르는 실제 손익분기는 **계단표**가 더 정확하다.
- 자료 중 수식으로 연결된 셀은 B4, B6, B8~B17이다. B5, B7, B18~B20은 참고용이다. B18 배달대행료는 연결돼 있지 않고 가정!C14:E14에 같은 값이 직접 입력돼 있다.

## 시트 안의 표기 규칙

- 파란 글씨는 직접 입력, 초록 글씨는 자료 시트 연결, 노란 칸은 바꿔도 되는 입력이다.
- 가정!F열의 "구분": 자료(원문 확인) / 가정(근거 약함) / 설정(케이스에서 준 값) / 계산.
- 경쟁비교·포지셔닝의 태그: [F] 확인한 사실, [I] 해석, [U] 미확인.
- 자료 시트의 행마다 출처, URL, 기준 시점, 비고(교체가 필요한 이유)를 함께 적는다. 값을 바꿀 때도 이 형식을 지킨다.

## 엑셀 다루는 법 (이 환경 기준)

- 이 PC에는 Excel과 LibreOffice가 없다. 수식을 다시 계산하는 엔진이 없으므로, `data_only=True`로 읽은 값은 마지막으로 저장할 때의 캐시다.
- **openpyxl로 저장하지 말 것.** 포지셔닝 시트의 차트(`xl/charts/chart1.xml`)가 사라진다. 수정은 xlsx 압축을 풀어 시트 XML(`xl/worksheets/sheetN.xml`, 시트 순서대로 1=가정 … 9=포지셔닝)을 직접 고친 뒤 다시 압축한다. 다시 압축할 때는 `[Content_Types].xml`을 첫 항목으로 넣는다.
- XML을 고친 뒤에는 `xl/workbook.xml`의 `<calcPr>`에 `fullCalcOnLoad="1"`을 둔다. 바뀐 수식 셀에는 예상 결과를 캐시 `<v>`로 넣어 둔다. `calcChain.xml`은 이미 제거했다.
- 새 텍스트는 `t="inlineStr"`로 넣으면 sharedStrings를 건드리지 않아도 된다. 스타일은 같은 열의 인접 행에서 `s` 값을 복사한다.

자주 쓰는 명령. Windows 콘솔이 cp949라서 `-I`와 함께 `-X utf8`을 붙여야 한다(`-I`가 `PYTHONIOENCODING`을 무시하기 때문).

```bash
# 모든 셀의 수식/값을 파일로 덤프
python -I -X utf8 -c "import openpyxl,sys;wb=openpyxl.load_workbook('market_model_case_student.xlsx');f=open(sys.argv[1],'w',encoding='utf-8');[print(ws.title,c.coordinate,repr(c.value),file=f) for ws in wb for r in ws.iter_rows() for c in r if c.value is not None]" dump.txt

# 캐시된 계산 결과 보기 (예: 손익 시트)
python -I -X utf8 -c "import openpyxl;w=openpyxl.load_workbook('market_model_case_student.xlsx',data_only=True)['손익'];[print([c.value for c in r]) for r in w.iter_rows(min_row=4,max_row=16)]"
```
