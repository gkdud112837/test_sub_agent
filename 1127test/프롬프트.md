교안 프롬프트를 이번 실습에서 실제로 어떻게 썼는지, 무엇을 보완했는지 정리했다.

## 1. 데이터 모델 초안 (1교시)
```text
spec.md 와 docs/data_spec.md(또는 data/products.json)를 읽고 docs/data_model.md 를 만들어 줘.
- 테이블 2~3개, 각 테이블: 열 이름 · 형식 · 설명 · 필수 여부
- 기본키와 외래키, 테이블 간 관계(1:N)
- 모든 테이블에 created_at 날짜 열
- 테이블마다 예시 행 3개(가상 데이터 표시)
- 데이터 트랙이면 재고 수량 · 주문 시각을 반드시 포함
SQL은 아직 쓰지 말고 설계 문서만.
```
보완 팁: "예시 행을 채우다 빠진 열이 나오면 표 아래에 기록"까지 요구하면 검증 과정이 문서에 남는다(이번에는 survey_id, ordered_at/created_at 구분).

## 2. 스키마 SQL (2교시)
```text
docs/data_model.md 를 읽고 supabase/schema.sql 을 써 줘.
- 테이블 생성 + 예시 행 insert(가상 데이터)
- 테이블마다 GRANT: anon 은 products select 만, service_role 은 전체
- 모든 테이블에 RLS 켜기 + products 읽기 정책 1개, 나머지 정책은 3교시에 추가
- 각 문장 위에 한국어 주석으로 무엇을 하는지
키 이름은 CLAUDE.md 에 적어 두고, 키 값은 묻지 말 것.
```
보완(리뷰 결과 반영): **"grant 앞에 revoke all로 기본 권한을 먼저 걷어 낼 것"**, "다시 실행해도 안전하게(if not exists · drop policy if exists)".

## 3. 로컬 SQL 검증 (교안 밖, 추가)
```text
Supabase 계정 없이 schema.sql · policies.sql · queries.sql 을 PGlite로 실행해 검증하는 스크립트를 만들어 줘.
anon · authenticated · service_role 역할과 auth.uid()를 흉내 내고,
가장 열린 기본 권한(anon에게 ALL)을 가정한 상태에서 보안 수용 기준을 PASS/FAIL로 출력.
```

## 4. AI 기능 계획 (3교시)
```text
spec.md 의 "AI 추천 사유" 기능과 보안 절을 기준으로 구현 계획을 세워 줘.
- 서버 함수에서만 GEMINI_API_KEY 사용
- 입력 검증 → DB 조회 → 프롬프트 → JSON 응답 검사 → 실패 시 기본 문구
- 브라우저 코드에 비밀 키가 들어가지 않는지 확인 단계
- 테이블별 RLS 정책 SQL 은 supabase/policies.sql 로
수용 기준 번호를 단계마다 표시해 줘.
```
보완 팁: "자유 입력은 프롬프트에 넣지 말 것", "추천 3개 사유를 한 번의 호출로" 두 줄을 넣으면 프롬프트 주입과 한도 소진을 같이 막을 수 있다.

## 5. 리뷰 서브에이전트 (4교시)
```text
서브에이전트를 하나 만들어 코드 리뷰를 맡겨 줘.
역할: 보안 · 품질 리뷰어. 파일은 수정하지 말 것.
범위: 이 브랜치에서 main 대비 바뀐 파일 전체
기준: spec.md 의 보안 절과 수용 기준
점검 항목: 1) 브라우저 코드에 비밀 키 · 환경변수 노출 2) 입력 검증 누락, AI 응답 형식 검사 누락
3) RLS 없이 접근 가능한 테이블 4) 오류 시 사용자에게 보이는 메시지
결과는 문제 · 파일 위치 · 심각도(높음/중간/낮음) 표로.
```
보완(실제로 쓴 것):
- "**근거 줄을 직접 열어 확인한 것만 적고 추측은 '확인 필요'로**"
- "'문제 없음으로 확인한 것'과 '보지 못한 범위'를 따로 적을 것"
- 수정한 뒤에는 **같은 에이전트에게** "기존 #1~#13을 해결/부분/미해결로, 새로 생긴 문제는 같은 표로" 재리뷰를 요청한다 → 새 문제 N1~N4가 나왔다.

## 6. SQL 집계 (과제)
```text
supabase/schema.sql 을 읽고 analysis/queries.sql 맨 위 주석의 질문 3개에 답하는 SQL 을 써 줘.
- SELECT 문만. 수정 · 삭제 문은 쓰지 말 것
- 쿼리마다 위에 질문을 주석(--)으로
- 날짜는 ordered_at AT TIME ZONE 'Asia/Seoul' 기준
쿼리마다 어떤 구문(WHERE · GROUP BY · JOIN)이 무슨 역할인지 한 줄씩 설명도 붙여 줘.
```
보완 팁: "결과 1개를 SQL 밖(CSV)에서 다시 세서 대조"와 "AT TIME ZONE을 뺀 결과도 같이 보여 줘"를 붙이면 검산과 시간대 교훈을 함께 얻는다.
