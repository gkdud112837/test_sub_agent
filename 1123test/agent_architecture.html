기준 리포트: SK증권 「IT 하드웨어 2027 연간전망 — IT 인플레이션 다음은?」(13쪽). 이 리포트가 만들어지는 절차를 4개 페이즈로 나누고, 페이즈 안의 에이전트는 모두 동시에 돌린다.

병렬 우선 · 같은 페이즈 에이전트는 서로 기다리지 않는다 공유 작업 공간 · 모든 결과는 workspace/에 파일로 남긴다 되돌아가는 경로 · R1~R5, 최대 2회 작성 ≠ 검토 · 쓰는 에이전트와 검토하는 에이전트를 나눈다 범위 정의는 메인 세션 · 별도 에이전트 없음

1목적 · 범위 메인 세션이 정해 workspace/00_brief/brief.md에 적는다

목적

기준 리포트와 같은 구성(표지 키워드 3개 → 요약 → 전년 리뷰 → 테마 3개 → Peer Valuation → Compliance)으로 IT 하드웨어 2027 연간전망을 쓴다. 결론은 "불확실한 업황에서 쇼티지가 이어지는 부품/기업을 고르는 기준"으로 끝난다.

  1. 26년 주가는 왜 상반기에 오르고 하반기에 꺾였나?
  2. 27년 세트 출하는 얼마나 역성장하나?
  3. LTA·증설은 호재인가, 위험인가?
  4. CR 압박을 견디는 쇼티지 부품/기업은?

R4report-writer → P1 분석 에이전트작성 중 근거가 모자람 (questions.md에 적음)질문받은 분석 에이전트만 보강. writer는 나머지 섹션 계속 작성
R5P1 분석 에이전트 → 메인 세션범위 밖 요청이거나 데이터를 구할 수 없음메인 세션이 brief.md를 고치거나 [확인필요]로 확정

같은 지적으로 2회 되돌아간 뒤에도 남으면 더 돌리지 않고 [확인필요]로 표시해 발간한다. 되돌아갈 때마다 run_log.json에 rerun_of로 이전 기록을 잇는다.

파일 규칙

  • 자기 폴더에만 쓴다. 병렬로 돌아도 덮어쓸 일이 없다.
  • 다른 에이전트 결과는 파일로만 받는다. 대화로 넘기지 않는다.
  • 다시 돌면 기존 파일을 덮어쓰고, 이전 판은 _v1처럼 남긴다.
  • run_log.json은 메인 세션만 쓴다. 에이전트는 결과 끝에 로그 요약을 붙여 돌려준다.
  • 검토 에이전트는 20_draft/를 직접 고치지 않고 30_review/에 지적만 남긴다.
