# 배운 점 — MCP 전후 비교 실습 (2026-11-25)

## 1. MCP가 해결하는 문제

- MCP를 안 쓰면 서비스 하나가 **API 주소 · 키 · 응답 파싱 · 스키마 · 도구 분기**를 전부 떠안는다. (Before 파일에 `# [불편]` 13곳)
- MCP를 쓰면 이 일이 **서버 한 곳**으로 모이고, 서비스는 `list_tools`로 묻고 `call_tool`로 시키기만 한다.
- 사용자가 받는 답은 똑같다(매출 합계 129,300,300원). **바뀌는 건 내부 구조**다.
- 진짜 이득은 줄 수가 아니라 **재사용 · 변경 한 곳 · 키 격리 · 도구 추가 시 서비스 수정 없음**이다. 자세한 비교는 [COMPARISON.md](COMPARISON.md).

## 2. MCP Python SDK 2.x에서 알게 된 것

- 1.x의 `FastMCP`는 **없어졌고** `MCPServer`로 바뀌었다. (`from mcp.server import MCPServer`)
- 포트 · 경로는 생성자가 아니라 `run()`에 넘긴다: `mcp.run(transport="streamable-http", port=9000)`. 기본 경로는 `/mcp`.
- 함수 이름 = 도구 이름, docstring = 설명, 타입 힌트 = 입력 스키마. 스키마를 손으로 쓸 필요가 없다.
- 에러는 `ToolError`로 던지면 `isError=True`와 메시지가 **LLM에게 그대로 보인다**. 다른 예외는 "Error executing tool"만 전달된다.
- 서버 로그는 MCP 레벨 로깅(deprecated) 대신 **파이썬 `logging`**으로 남긴다.
- 기본 host는 `127.0.0.1`이고 DNS rebinding 보호가 기본 적용된다 → 로컬 실습엔 추가 설정이 필요 없다.

## 3. 외부 API를 다루며 알게 된 것

- **날씨 API**는 도시명을 모른다 → 도시 → 위도 · 경도 표가 필요하다.
- **수출입은행 환율 API**
  - 숫자가 `"1,346.6"` 같은 문자열 → 쉼표 제거 후 변환
  - `JPY(100)`은 100엔 기준 → 100으로 나눠야 1엔 값
  - 주말 · 공휴일 · 오전 11시 전엔 빈 목록 → 최근 영업일까지 거슬러 간다 (오전엔 11-24, 오후엔 11-25 값이 나왔다)
- **Gemini API**
  - `gemini-3.8-flash`가 503(수요 과다) · 504를 계속 냈다. 키 문제가 아니라 **구글 쪽 용량 부족**이었다. → 모델을 바꾸거나 재시도로 피한다.
  - 무료 등급은 **모델당 분당 5회** 제한(429). 도구를 쓰는 질문 하나에 Gemini를 3~4번 부르므로 금방 찬다.
- 실패 메시지에 **키가 담긴 URL이 새지 않게** 예외 종류만 남기는 처리가 필요하다.

## 4. "MCP는 지는 중인가?" — MCP vs CLI 논쟁

읽은 글: 김평안, 「[MCP는 이제 정말 필요 없을까? — MCP vs CLI](https://brunch.co.kr/@pyan/38)」 (2026-06-12)

**비판의 요지**
- MCP는 복잡하고, 도구 설명이 AI의 컨텍스트(토큰)를 많이 차지한다(**컨텍스트 오염**).
- CLI는 검증된 방식이고, 도구 조합이 자유롭고, 모델이 이미 많이 학습했다.

**글의 결론 — 사라질 기술은 아니다**
- 진짜 문제는 MCP가 아니라 **AI에게 불필요한 정보를 한꺼번에 주는 방식**이다.
- AI 친화적인 CLI를 만들려면 결국 기능 설명 · 인증 관리 · 단계적 기능 발견이 필요해지고, **MCP가 주는 구조를 다시 만들게 된다**.
- CLI = 유연함 · 단순함, MCP = 표준화 · 확장성. 서로 대체하기보다 각자 발전 중이다.

**내 정리**
- "지는 중"이 아니라 **"쓰는 방식이 다듬어지는 중"**이다.
- 업계는 MCP를 버리기보다 고치는 쪽: 필요한 도구 설명만 **나중에 불러오기**, **코드 실행**으로 결과만 받아 오기.
- 언제 무엇을 쓸까

  | 상황 | 더 맞는 쪽 |
  |---|---|
  | 여러 AI 서비스 · 도구(Claude Code 등)가 같은 연결을 공유 | MCP |
  | 연결 대상이 자주 바뀌거나 늘어남 | MCP |
  | 키를 서비스에서 떼어 한 곳에서 관리 | MCP |
  | 혼자 쓰는 개발 도구, 연결 대상이 1~2개 | CLI · 스크립트 |
  | 도구가 수십 개라 설명이 컨텍스트를 압박 | MCP + 지연 로딩 / 코드 실행 |

## 5. 한 줄 요약

> MCP의 가치는 "AI가 외부 기능을 부르는 방법"을 **한 곳에 표준으로** 두는 것이다.
> 비용(서버 운영 · 컨텍스트)이 있으니, 공유할 서비스가 여럿이거나 연결이 자주 바뀔 때 쓰면 이득이 크다.
