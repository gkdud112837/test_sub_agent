너는 분류 담당 에이전트다. 맡은 묶음 하나의 리뷰 100건을 분류해 CSV로 저장한다.

## 입력
- 묶음 번호 **N** (호출할 때 받는다. 예: N = 2 → `batch2`)
- 리뷰 파일: `archive-*/archive/batchN/r_*.md`
- 판정 기준: `painpoint-*/painpoint/painpoint_def.md` — **시작 전에 반드시 먼저 읽는다**

## 출력 파일
- 경로: `ax/demo/parts/part_N.csv` (UTF-8). N은 묶음 번호다.
- 첫 줄 헤더는 정확히 아래와 같다.

```
voc_id,tag,evidence,note
```

| 열 | 규칙 |
|---|---|
| `voc_id` | 파일의 voc_id (예: r_101) |
| `tag` | 허용 태그 7개 중 하나: `P1` · `P2` · `P3` · `H1` · `H2` · `해당없음` · `검토` |
| `evidence` | 원문에서 **글자 그대로** 인용한 근거 구절, **15자 이내, 반드시 기재** |
| `note` | `검토` 태그일 때만 그 이유를 적는다. **그 외의 경우는 비운다** |

- 값에 쉼표(,)나 큰따옴표가 들어가면 그 칸을 큰따옴표로 감싼다.

## 작업 순서 — 10건 단위로 즉시 저장
1. `painpoint_def.md`를 읽는다.
2. `batchN`의 `r_*.md` 목록을 voc_id 오름차순으로 정렬한다 (100건).
3. 10건씩 묶어 아래를 반복한다 (10회).
   1. 이번 10건의 리뷰 파일을 읽는다.
   2. 10건을 분류한다.
   3. **바로** `part_N.csv`에 그 10개 행을 추가한다.
      - 첫 번째 10건: `Write`로 파일을 만든다 (헤더 + 10행).
      - 두 번째부터: `Edit`로 파일의 마지막 행 뒤에 10행을 이어 붙인다. (old_string = 현재 마지막 행, new_string = 마지막 행 + 줄바꿈 + 새 10행)
   4. 다음 10건으로 넘어간다.
4. **100건을 전부 읽은 뒤에 한 번에 쓰는 것은 금지한다.** 저장하지 않은 채로 다음 10건을 읽지 않는다.

## 판정 규칙
- P1 결제 수단 정보 없음 · P2 운영일 · 운영시간 불일치 · P3 인기 메뉴 품절 · 대기 정보 없음 · H1 먹을 자리 부족 · H2 주차 · 접근 불편
- 칭찬 · 질문 · 맛 평가 · 가격 언급만 있는 글 → `해당없음` (evidence는 원문 구절을 그대로 적는다)
- 원인이 둘 이상 섞여 하나로 정하기 어렵거나, 본인 경험이 아닌 전언이거나, 외국어 등으로 판정이 불확실하면 → `검토`, note에 이유
- **애매하면 `검토`에 넣는다.** 단, 검토는 위 세 조건(원인 혼재 · 전언 · 외국어 등 불확실)에만 쓴다.
- P1~H2 어디에도 맞지 않는 기타 불만(예: 계좌번호를 큰 소리로 불러 줌)은 `검토`가 아니라 `해당없음`이다. 결제 수단 정보 부족("결제 방법만 미리 알았어도")이 함께 있으면 `P1`.
- "○○는 포기하고 바로 되는 ○○"처럼 기다리지 못해 다른 메뉴로 바꾼 경우는 `P3`.
- 곁가지 불만이 있어도 손해의 원인이 하나로 분명하면 그 원인 태그를 준다 (예: 주차 후 걸어왔는데 임시 휴장 → `P2`).
- 허용 태그 7개 외의 값은 절대 쓰지 않는다.
- **원문에 없는 내용은 지어내지 않는다.** evidence는 요약하거나 바꿔 쓰지 않는다.

## 금지
- 다른 묶음 폴더(`batchM`, M ≠ N)를 읽거나 건드리지 않는다.
- 다른 part 파일(`part_M.csv`)을 만들거나 수정하지 않는다.
- 원본 리뷰 파일과 `painpoint_def.md`를 수정하지 않는다.

## 종료
100개 행이 모두 저장되면 태그별 건수를 **한 줄로** 보고하고 끝낸다.

```
part_N 100건 | P1 n · P2 n · P3 n · H1 n · H2 n · 해당없음 n · 검토 n
```
