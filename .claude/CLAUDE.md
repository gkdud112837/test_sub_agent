# 프로젝트: 서문시장 야시장 AX (team-demo · 수업 예시)

## 목적
서문시장 야시장 식품 구매자의 VOC를 분석해 페인포인트 → 산업 구조 · 밸류체인 → AX 기회 → spec · MVP로 이어 간다.

## 폴더

| 경로 | 내용 | 규칙 |
|---|---|---|
| `archive-*/archive/batch1~3/r_XXX.md` | VOC 300건 원본 | **수정 금지** |
| `archive-*/archive/metadata.csv` | voc_id · source · date · file 목록 | 범위 점검의 기준 |
| `painpoint-*/painpoint/painpoint_def.md` | 페인포인트 정의서 (P1~P3, 보류 H1 · H2, 분류 규칙) | **수정 금지** |

## 아카이브 정리 — CSV 형식 (`output/voc_tags.csv`, UTF-8 BOM)

| 열 | 내용 |
|---|---|
| `voc_id` | r_001 ~ r_300 |
| `source` · `date` · `file` | metadata.csv 그대로 |
| `tag` | 허용 태그 7개 중 하나 |
| `quote` | 원문 근거 구절 — 글자 그대로, 15자 이내, **모든 행 필수** |
| `근거유무` | 인용이 원문에 있고 태그의 근거가 되면 `Y` |
| `note` | `검토`는 이유 필수, `해당없음`은 사유 |
| `원문` | VOC 본문 (채점관 대조용) |

## VOC 분류 규칙 (painpoint_def.md 기준)
- 허용 태그 7개: `P1` 결제 수단 · `P2` 운영일 · 시간 · `P3` 품절 · 대기 · `H1` 먹을 자리 · `H2` 주차 · 접근 · `해당없음` · `검토`
- 칭찬 · 질문 · 맛 평가 · 가격만 있는 글 → `해당없음`
- 원인 둘 이상 혼재 · 본인 경험이 아닌 전언 · 외국어 등 불확실 → `검토` (note에 이유)

### 판정 보충 기준 (2026-11-10 채점 결과 반영 · 정의서는 수정하지 않음)

| 상황 | 판정 | 예 |
|---|---|---|
| P1~H2 어디에도 맞지 않는 기타 불만 (검토 3조건에 해당하지 않음) | `해당없음` | 계좌번호를 큰 소리로 불러 줌 (r_120 등) |
| 위 불만에 결제 수단 정보 부족이 함께 드러남 | `P1` | "결제 방법만 미리 알았어도" (r_055 · r_183) |
| "○○는 포기하고 바로 되는 ○○" — 기다리지 못해 다른 메뉴로 바꿈 | `P3` | r_036 · r_178 · r_226 |
| 곁가지 불만이 있어도 손해의 원인이 하나로 분명함 | 그 원인 태그 | 주차 후 걸어왔는데 임시 휴장 → `P2` (r_241) |
| 같은 문장 틀은 묶음이 달라도 같은 태그 | — | 묶음 간 일관성 유지 |

## ✅ 품질 게이트 — VOC 분류 결과는 아래를 순서대로 모두 통과해야 확정한다

| 단계 | 확인 항목 | 통과 기준 | 확인 주체 | 관제 화면 표시 |
|:---:|---|---|---|---|
| **1** | **ID 범위** — VOC 파일을 읽을 때 voc_id 누락 · 중복 · 초과 확인 (metadata.csv · batch 파일 대조) | 누락 0 · 중복 0 · 초과 0 | 채점관 **① 범위 점수** | 채점 채널 ① |
| **2** | **근거** — 모든 행에 원문 인용이 있고, 원문과 글자 그대로 일치하며, 근거 유무가 `Y` | 인용 누락 0 · 불일치 0 | 채점관 **② 근거 판정** | 채점 채널 ② |
| **3** | **태그** — 모든 태그가 허용 목록 7개 안에 있고 상식적으로 맞는지 | 허용 밖 태그 0 | 채점관 **③ 상식 점수** | 채점 채널 ③ |
| **4** | **검토 비율** — `검토` 태그가 전체의 5% 이하, 모든 `검토` 행에 이유 기재 | ≤ 5% (300건 기준 15건 이하) · 이유 누락 0 | `check_gates.py` | **검토 숫자 (건수 · 비율)** |
| **5** | **채점 합격선** — 채점 세 묶음(① 범위 · ② 근거 · ③ 상식) 모두 | **각 89점 이상** | 채점관 (`grader` 에이전트) | **채점 채널 (3개 점수 · PASS/FAIL)** |
| **6** | **골든셋 동의** — 사용자가 제공한 10개 행과 태그 비교 | **10개 중 9개 이상 일치** | `check_gates.py` + 사용자 | 골든셋 n/10 |
| **7** | **승인** | 사용자가 직접 "승인" | **사용자만** (Claude는 승인 불가) | 승인 대기 / 완료 |

### 관제 화면 필수 요소

| 요소 | 내용 |
|---|---|
| 검토 숫자 | 검토 건수 · 전체 대비 비율 · 이유 누락 건수 |
| 채점 채널 | ① 범위 점수 · ② 근거 판정 · ③ 상식 점수 — 점수 / 기준(89) / PASS · FAIL |
| 골든셋 | 사용자 제공 10행 동의 수 (기준 9/10) |
| 승인 상태 | 대기 / 사용자 승인 완료 |

### 진행 규칙
- 단계 1~6 중 하나라도 FAIL이면 분류를 고친 뒤 **처음부터 다시** 점검한다.
- 채점관(`grader`)은 분류한 쪽과 독립적으로 채점하며 CSV를 고치지 않는다.
- 골든셋 10행은 사용자가 제공한다. 받기 전에는 6단계를 "대기"로 표시하고 임의로 만들지 않는다.
- 1~6을 모두 통과해도 **사용자가 승인하기 전에는 결과를 확정 · 배포하지 않는다.** Claude가 스스로 승인 처리하지 않는다.

## 🤖 에이전트 (`.claude/agents/`)

에이전트는 앞으로 모두 `.claude/agents/` 폴더 아래에 만든다.

| 에이전트 | 역할 | 입력 | 출력 | 핵심 규칙 |
|---|---|---|---|---|
| **review-tagger** | 분류 담당 | 묶음 N의 리뷰 100건 (`batchN/r_*.md`) | `ax/demo/parts/part_N.csv` | 10건 읽을 때마다 **즉시** 10행 추가 저장 (끝에 한 번에 쓰기 금지) · 끝나면 태그별 건수 한 줄 보고 |
| **review-grader** | 채점 담당 | `ax/demo/parts/part_*.csv` + 원문 | `ax/demo/scorecard.md` (점수표 · 관제 화면) | 세 묶음(범위 · 근거 · 상식) 채점 · part 파일 수정 금지 · 승인 처리 금지 |

### review-tagger CSV 규칙

| 열 | 규칙 |
|---|---|
| 헤더 | 첫 줄은 정확히 `voc_id,tag,evidence,note` |
| `tag` | 허용 태그 7개 외의 값 금지 · **애매하면 `검토`** |
| `evidence` | 원문에서 **그대로** 인용한 근거 구절 · **15자 이내 · 필수** · 원문에 없는 내용은 지어내지 않음 |
| `note` | `검토`일 때만 이유 기재 · 그 외에는 비움 |
| 범위 | 자기 묶음 폴더와 자기 part 파일만 다룸 · 다른 묶음 폴더 · 다른 part 파일은 건드리지 않음 |

### 실행 흐름
1. 묶음 1 · 2 · 3에 `review-tagger`를 병렬 실행 → `part_1.csv` · `part_2.csv` · `part_3.csv`
2. `review-grader`로 채점 → `scorecard.md` (관제 화면: 검토 숫자 · 채점 채널)
3. 품질 게이트 1~6 확인 → **사용자 승인** (7단계)

## 분석 표기 원칙
- [F] 출처 확인 사실 · [I] 해석 · [U] 미확인 · [V] VOC 근거
- 밸류체인은 네 층(활동 · 이해관계자 · 돈 ⇐ 역방향 · 데이터 ⇢). 마커는 병목 2 · 비용 2 · 기회 3, 단계당 최대 2개

## 작업 습관
- 한국어로 답한다
- Python은 `python -I -X utf8`로 실행한다 (Windows 콘솔 한글 깨짐 방지)
- 대량 분류는 `review-tagger` 묶음별 병렬 실행 → `review-grader` 채점 → 관제 화면 보고 → 사용자 승인 대기
